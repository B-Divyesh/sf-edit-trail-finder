How it works

Index editing steps in three commands

Edit Trail reads each supported sidecar, records active operations, and builds a small local index you can search.

  1. 01

    Scan sidecars

    Walk XMP, DOP, and PP3 files recursively. Malformed sidecars are recorded as warnings, and scanning continues.

  2. 02

    Normalise operation names

    Map editor-specific names and enabled states into one visible editing step.

  3. 03

    Query combinations

    Require all operations or match any, then print paths, JSON, CSV, or a static report.

CLI reference

CLI commands for sidecar searches

Index an archive, find matching files, list operation names, or write an offline report.

archive / bash
$ edit-trail index ~/Pictures
Indexed local sidecars; warnings are recorded
→ .edit-trail.json
query / bash
$ edit-trail find -o denoise -o crop --match all
MATCHES
/Archive/2026/night-market/DSC_1842.NEF
  darktable · crop, denoise, exposure
audit / bash
$ edit-trail report --output audit.html
Offline report written to audit.html
pipeline / bash
$ edit-trail find -o masking --json | jq length
[...]

CLI behavior on large archives

  • Continues past malformed sidecars
  • Honours darktable history boundaries
  • Normalises common operation aliases
  • Uses exit code 3 for no matches
  • Produces a self-contained offline report
